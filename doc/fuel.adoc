[#xactor-fuel]
== Fuel

Every message belongs to an execution, named by a `correlation_id`. A
delivery from the host opens its execution, and every message that delivery
causes, directly or through any number of actors, belongs to the same one.
An execution has one reservoir of fuel, the `fuel` of the scheduler's
`budgets`, and every actor in it pays from that reservoir: one unit for each
message it sends and each timer it arms, and the units it declares for its own
work.

Fuel exists so that the total work of an execution is bounded, whatever shape
its messages take: a chain of messages, a fan-out, two actors that answer each
other forever, or an actor that computes a lot and sends little. A host that
runs actors it does not trust, or that must answer within a budget, knows that
every delivery it makes ends.

Each send takes one, so the fourth turn finds none: its send fails with
`resource_limit`, nothing is sent, and the run ends after four deliveries. A
refusal is a value the logic decides about. The relay prints it and returns
success, so it stays `active`, ready for the next execution.

input a correlation of its own.

returns the failure, which ends it with the status `error`, and `error_of`
keeps the code.

The rules of fuel:

* *What costs.* Inside a turn, `send` and `reply` cost one unit, `wake_at`,
  with a key or without, one unit, and `spend(n)` n units, all from the
  execution of the message being handled. `spawn_child`, `stop_child`,
  `stop`, `finish`, `cancel_timer`, `self`, `parent`, `now` and `fuel` cost
  nothing, and so does a delivery from the host.
* *All or nothing.* What the execution cannot pay fails with
  `resource_limit` and changes nothing: no message is enqueued, no timer
  armed, no unit spent. `spend` takes all its units or none, and a keyed
  `wake_at` that is refused leaves the timer under its key as it was.
* *Opening an execution.* The first `deliver`, `clock_tick` or `release_next`
  of a correlation opens its execution with the whole budget. A timer that a
  tick releases belongs to the tick's execution, and releasing it costs
  nothing, since arming it was paid (<<xactor-timers>>).
* *Reading it.* `turn.fuel()` is the fuel the execution of the message being
  handled has left, and the scheduler's `fuel_of(correlation)` the same from
  outside; for an execution not yet opened, `fuel_of` is the whole budget.
