[#xactor-determinism]
== Rules that keep a run deterministic

xactor guarantees the order of a run. One first-in first-out mailbox for each
actor and one first-in first-out queue of actors make the order of deliveries
depend on the order of the messages alone, under every driver; fuel bounds
every execution; and time moves only when the host brings it. xactor itself
reads no clock, no disk and no network, blocks in no turn, keeps no static
mutable state, so that two schedulers in one process are independent, and
throws no exception of its own. Two schedulers built with the same budgets
and fed the same deliveries record equal envelope logs
(<<xactor-drivers-log>>).

An actor can still break that guarantee, by letting something other than its
messages decide what it does. These rules keep it from doing so:

* *Read no clock in a turn.* Take the time from `turn.now()`, or from the
  message a timer brings (<<xactor-timers>>).
* *Read nothing from the world in a turn, and never wait.* The host reads a
  file or the network, and delivers what it read as a message. A turn that
  waits holds up every actor, since they all run on one thread. Writing out,
  as the examples print, decides nothing, and is safe.
* *Draw no random number but from a seed that a message brought.*
* *Keep no static mutable state.* Two schedulers in one process must stay
  independent, as xactor's own are.
* *Throw nothing, and return an error instead.* xactor catches nothing: an
  exception thrown by a `handle` leaves `run_one` and the driver in the middle
  of the run, where an error returned ends one actor and the run goes on
  (<<xactor-logic>>).
* *Keep no reference to the turn or to a message beyond the turn.* Both are
  gone once `handle` returns; copy what is needed.

A program checks that its run is deterministic by running the same
deliveries twice, recording both runs and comparing the envelope logs, as
xactor's own tests compare its drivers (<<xactor-testing>>).
